
## Dimer binder design campaign

We want to design a pH-responsive binder for EGFR that only binds EGFR at low pH. The goal is to design a binder that dimerizes at pH 7.4 via a dimerization interface that contains neutral histidines, similar as in https://www.science.org/doi/10.1126/science.aav7897. Upon lowering the pH, the dimerization interface should fall apart, exposing the actual binding interface for the EGFR receptor. Finally, we will link the two binder monomers with a flexible linker to increase the affinity for the intramolecular interface. This strategy allows us to do pH agnostic design, where we ignore protonated histidines during the design because we only need to design a stable interface containing histidine hydrogen bond networks at neutral pH. Additionally, our ideal binder binds to both human and mouse EGFR. 

Other hard requirements:
- The complete sequence (binder monomer - linker - binder monomer) can be no more than 250 amino acids. Let's reserve 20 aa for the linker, that leaves 115 aa per binder monomer.
- The binder interface should not be located too close to the C-terminus - wet lab validation will fuse the C-terminus to a GFP and splitstrep tag, so a binding interface too close to that terminus might be inhibited by the tag. Note this is a two-sided constraint, not a one-sided one: the C-terminus must stay clear of the EGFR epitope (this requirement) while still being reachable from the partner monomer's N-terminus across the dimerization interface (phase 2). Both are recorded as separate metrics; see `dimer_binder_plan.md` §2.1.

Here is my intended pipeline:

**Phase 1 covers initial binder design for EGFR.** Crucially, we want to obtain a good binding interface regardless of pH. Ideally the binder targets a hydrophobic patch: suggested hotspots (human EGFR numbering) are L325, P349, F412, V417, I467. We want to avoid binding sites on EGFR that contain histidines, because their protonation at low pH might ruin the interface. 

1. Backbone design: bindcraft 2 with multi-target optimization (human and mouse EGFR). (NOTE: multi-target is not supported by the bindcraft2 wrapper here - `run_bindcraft2.py:438-446` hard-codes a single-element `targets` list. Reviving phase 1 means editing the wrapper, or designing against one ortholog and screening the other.) Here we want to record the position of the C-terminus relative to the EGFR target. Calculate the binder center of mass, the binder-target interface center of mass, calculate the normal plane to that vector, and record on which side of the plane the C-terminus sits, together with its distance to the interface. Per the hard requirement above this is a two-sided criterion, so record both numbers rather than filtering on one.

2. Redesign of successful binders with Atomium and filtering using a structure predictor. 

Important: we will initially skip phase 1 and start designing phase 2 around the binders in sapia-runs-toon/inputs/bc2_output_for_anthony/ . These have already been designed against our two targets, so we can focus on the dimerisation. Implementing phase 1 and the connection to phase 2 can wait.

**Phase 2 covers dimerisation and Hbond network design**
1. Input pdbs should have both target and binder. Select residues that are at the binding interface (for example as InterGroupInterfaceByVector does, although another pyrosetta function could be used if it is more appropriate, default 8 angstrom distance). Extract the binder into a single pdb file and retain which binder residues are involved in the interface. Clean up the pdb file (rename to chain A, renumber sequence if necessary) and we should retain a aa chain:res id mapping for the binder monomer pdb to the binder monomer in the target input. This mapping should be able to requested multiple design steps down the line. (NOTE: the interface residue list and the mapping must be table COLUMNS, not accompanying files. A sidecar file does not survive the generation boundary into the dock and network tables, which is exactly where they are needed. The mapping has to survive three separate renumberings - chainsel's extraction, rpxdock's forced 1..N-per-chain dump, and hbdesigner's own offset.)
2. Input the binder into RPXdock and run with C2 symmetry. (NOTE: `--use-orig-coords` is required. The default rpxdock dump is backbone-only - N/CA/C/O/CB plus a CEN pseudo-atom - which would make the fa_rep clash score in step 4, the rotamer transplant in step 6, and sequence-based remapping all meaningless. The dump also renumbers 1..N per chain.)
3. Filter for good docks. Good docks are based on rpxdocks own scoring. We want docked dimers where the dimerization interface is close to the binder-EGFR interface, but ideally does not overlap (completely). This can be achieved by calculating the center of masses of both interfaces and filtering on the distance. Ideally, the C-terminus of one monomer should be placed in reach of the N-terminus of the other binder. (NOTE: a straight terminal-Calpha distance does NOT suffice, and the original plan to use one has been dropped. It is only a lower bound: where the direct vector passes through the dimer body the linker has to go around, and the route can be far longer than the chord. Measured on 40 real docks the straight-line distance was 10.4-50.3 A, i.e. always inside a ~20 aa budget - the constraint never bound, which is exactly the signature of a metric that is too permissive to discriminate. The real number is the shortest path through solvent-accessible space, computed by the standalone `linkpath` tool; see `dimer_binder_plan.md` §4.2. The obstacle set for that path is the dimer ALONE: at pH 7.4 the construct is closed and EGFR is not bound, so routing around EGFR would invent an obstruction that is not there when the linker matters.) These two metrics position the dock, but they say nothing about occlusion - that is step 4's job, and both are needed.
4. Superpose dimerized binder onto monomer binder-EGFR structure (using the binder in the binder-EGFR complex, and one of the monomers of the dimer, but apply the rigid body transformation to the entire dimer) and calculate a clash score for the second binder copy and the EGFR (fa_rep) -> continue with binder dimers that show strong clashes between the second binder copy and EGFR (because we want the dimer to prevent binding). Export a new output file with the binders in the position after the rigid body transformation (without the target) - this will simplify the next step. (NOTE: pyrosetta cannot do this. The pyrosetta tool has no superposition or rigid-body capability at all - only FastRelax plus a CA_rmsd of the relaxed pose against its own start. Nothing in the workspace can superpose on a chosen residue subset and apply the transform to everything, which is why the `dimerfit` tool has to be built.)
5. Use HBdesigner to design Hbond network for a binder dimer at the dimerization interface. Prefer HisN --- H donor bonds paired with HisH - carboxylate hbonds for pKa adjustment. HBdesigner can handle symmetric interfaces (`--symm-chains`, experimental upstream). Check flaggs for what might help! Record how many of the designed network positions coincide with binder-EGFR interface positions - we would rather have no overlap at all. (NOTE: this step and the transplant below were swapped relative to the original ordering. HBdesigner writes `to_pdb(unk_to_gly=True)` - every non-network position comes back as glycine - and there is no per-residue "do not design here" flag, so transplanted rotamers handed to it would simply be erased. `--guide-res`/`--guide-radius` can steer the network away from the EGFR face but cannot forbid positions.)
6. Identify the binder residues that are part of the binder-EGFR interface, and transplant them from the binder-EGFR structure to the dimer structure (for both copies). Do the correct rigid body transformation to place them on the second binder copy. I want the exact same rotamers as in the input file. Where a position is both an hbond network residue and a binder-EGFR interface residue, the network residue wins.
7. Filter for designs with histidines in the hbond network
8. Fill in the remainder of the sequence with atomium (keeping the binder-egfr interface residues intact, as well as the hbond network residues)
9. Validate using structure prediction with boltz. Predict the dimer structure, the egfr-monomer structure, and the egfr-dimer structure. (NOTE: this tests foldability and assembly, not the pH switch - no structure predictor is pH-aware. The switch itself is currently unmeasured; see `dimer_binder_plan.md` §2.2 and §8.)
